# Kernel rank, d95 and participation ratio vs spatial coarse-graining

Reproduces the spin-wave-reservoir (SWR) feature-matrix dimensionality analysis:
how the numerical **rank**, **d95** (number of principal components carrying 95 %
of the across-sample variance), and **participation ratio (PR)** of the reservoir
feature matrix Ψc behave as the `m_z` field is spatially coarse-grained from the
native 50×50 grid down to 4×4.

## What the analysis does

Each of the **256 reservoir runs** (the 16×16 direct-temporal-encoded input
sample space) is a `(201 frames, 50, 50)` `m_z` field. For each spatial grid
`g ∈ {50, 40, 30, 20, 10, 8, 6, 4}`:

1. Area-average (`cv2.resize`, `INTER_AREA` — the Nyquist-respecting low-pass)
   every `(run, frame)` map to `g×g`.
2. Flatten the full spatiotemporal volume per run → a `256 × (201·g²)` feature
   matrix Ψc, mean-centred across the 256 samples.
3. One economy SVD → kernel rank at ε ∈ {1e-3, 1e-2, 5e-2}, raw numerical rank,
   d50/d95/d99, participation ratio, and the singular-value spectrum.

`spatial_rank_per_frame.py` is a sub-analysis: it ranks **each of the 201 frames
separately** (a `256 × g²` matrix per frame), so for coarse grids the rank ceiling
is `g²` rather than the sample count — a clean test of whether the `g²` spatial
features stay independent past the spatial-Nyquist scale.

## Input data

| Variable | Default value | Description |
|---|---|---|
| `CUBE_PATH` | `/path/to/sw_disk_mz_cube.npy` (set this env var) | NumPy array, shape `(256, 201, 50, 50)`, float32. The 45 mT / 800 MHz spin-wave-disk `m_z` cube. **~5 GB — not bundled.** |

Set the location before running the compute scripts:

```bash
export CUBE_PATH=/path/to/sw_disk_mz_cube.npy   # Windows: $env:CUBE_PATH="..."
```

**Provenance:** the cube is the 16×16 / 256-run / 50×50 drive cube of the
45 mT / 800 MHz spin-wave-disk substrate. The mumax³ source and the
`(256, 201, 50, 50)` CSV→cube assembler (`build_cube.py`) that produce it live
at [`../../simulator/`](../../simulator/) — the same substrate analysed in
the sibling [`../xor_chequerboard/`](../xor_chequerboard/) experiment (at 32×32
input resolution). The raw cube is multiple GB and is not bundled; see *Data
availability* in the top-level README.

## How to reproduce

All scripts resolve paths relative to their own location, so run them from this
folder. The `.npz` caches must stay alongside the scripts (the figure scripts
read them from the script directory).

**A. Recompute the metrics** (needs `CUBE_PATH`; ~minutes, CPU-only,
RAM-bound by the 256×(201·50²) matrix — run on a Linux workstation that has
the cube on local disk):

```bash
python kernel_rank_cg.py            # → kernel_rank_results.npz, montage_data.npz
python spatial_rank_per_frame.py    # → spatial_rank_results.npz   (for Fig. S9.2)
```

Both print a summary table to stdout (the values reproduced below). To **skip**
this step, use the bundled `.npz` caches as-is.

**B. Regenerate the figures** (only needs numpy + matplotlib; no cube required):

```bash
python make_figures.py        # → figures/fig1..5_*.png  (supporting analyses)
python make_fig_s91.py        # → figures/figS91_kr_pr.png   (Section S9.1 panel)
python make_fig_spatial.py    # → figures/figS92_spatial_rank.png (Fig. S9.2)
```

**C. Rebuild the Supplementary Table .docx** (OPTIONAL; Windows + Microsoft Office
only — uses Office's `MML2OMML.XSL` to emit native Word equations):

```bash
python build_docx_s91.py      # → SI_S9_1_Kernel_Rank.docx
```

⚠ Caveats for step C: (1) it requires the file
`C:\Program Files\Microsoft Office\root\Office16\MML2OMML.XSL` (edit the `XSL`
constant if the Office path differs); (2) it writes the `.docx` **four directory
levels above the script** (`os.path.join(HERE, "..","..","..","..")`). In this
package that resolves above the repo root; the figures and table data alone
are sufficient for the scientific compute — this script is a
manuscript-assembly helper.

## Reference result (Supplementary Table 2 / Table S9.1)

| Grid | D = X·T | d95 | PR | rank(Ψc) | KR (ε=1e-3) |
|---|---|---|---|---|---|
| 50×50 | 502,500 | 26 | 24.3 | 255 | 255 |
| 40×40 | 321,600 | 26 | 24.1 | 255 | 255 |
| 30×30 | 180,900 | 26 | 24.1 | 255 | 255 |
| 20×20 | 80,400 | 26 | 23.7 | 255 | 255 |
| 10×10 | 20,100 | 25 | 20.6 | 255 | 255 |
| 8×8 | 12,864 | 23 | 17.2 | 255 | 255 |
| 6×6 | 7,236 | 19 | 13.4 | 255 | 255 |
| 4×4 | 3,216 | 22 | 8.4 | 255 | **227** |

`rank(Ψc)` is the **raw numerical rank** (full = N−1 = 255 at every scale). Note
the **strict kernel rank** at ε=1e-3 is also 255 from 50×50 through 6×6 but drops
to **227 at 4×4** — the only scale where it leaves the ceiling. Quote the
appropriate column depending on which "rank" the surrounding text means.
